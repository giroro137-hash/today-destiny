# 오늘의 운명 예고편 - 서버형 MVP

## 실행
- Node.js 18 이상 설치
- 프로젝트 폴더에서 `npm install`
- `.env.example`을 `.env`로 복사하고 APP_SECRET을 긴 무작위 문자열로 변경
- `npm start` 후 `http://localhost:3000` 접속

## 구현 (v2)
무료 운세(시간대별·연애·금전·직장), 잠금형 프리미엄 미리보기, 4개 상품(2,900 / 9,900 / 19,900 / 22,900원). 운세 생성은 src/reading.js, 가격 기준은 src/server.js의 products.

Express + SQLite 서버, 무료 체험 기록 DB 저장, 무료 요청 중복 차단, 상품별 주문 생성, 요청 제한, 모바일 웹 UI, 결과 공유.

## 정식 출시 전 반드시 필요한 작업
1. 현재 운세 문구는 예시입니다. 만세력/간지/음력 변환을 포함한 실제 사주 계산 엔진과 전문가 검수가 필요합니다.
2. 무료 1회는 임시 IP 기반입니다. 가족·공용망 사용자가 영향을 받거나 VPN으로 우회할 수 있습니다. 정식 서비스는 인증 계정 ID 기준으로 제한해야 합니다.
3. 결제는 아직 승인되지 않습니다. 주문 레코드만 생성하며 501 응답을 돌려줍니다. PortOne 등 결제사 상점/채널 설정, 서버 결제 검증, 웹훅, 환불·취소 처리가 필요합니다.
4. HTTPS, 비밀키 관리, 백업, 개인정보 처리방침·이용약관·환불정책을 준비하세요. 생년월일과 출생 시간은 개인정보로 취급하고 수집 최소화/보유기간을 검토해야 합니다.

## 결제 연결에 필요한 운영자 정보
PortOne 계정의 Store ID, 테스트 결제 채널 키, API Secret. 이 값은 공개 채팅에 올리지 말고 배포 환경변수에 입력해야 합니다.

## 법적 출시 체크리스트 (결제를 열기 전 필수)
1. 사업자등록 → 통신판매업 신고(직전년도 거래 50회 미만이거나 간이과세자는 면제될 수 있으니 관할 구청·세무서에서 확인). 신고번호는 사이트 하단에 표시해야 합니다.
2. `public/business.js`의 상호·대표자·사업자등록번호·신고번호·주소·연락처·이메일·개인정보 보호책임자·시행일을 채우세요. 비어 있으면 화면에 빨간 [입력 필요]가 보입니다.
3. `privacy.html`의 호스팅 업체·결제사·무료체험 기록 보관기간을 채우세요.
4. 약관·개인정보처리방침·환불 안내는 초안입니다. 출시 전 변호사 검토 또는 한국소비자원(1372) 상담을 받으세요. 특히 `refund.html`의 디지털콘텐츠 청약철회 제한은 요건(사전 고지·시험 사용)을 갖췄을 때만 유효합니다.
5. PortOne 연동과 서버 결제 검증을 마친 뒤에만 `.env`의 `PAYMENTS_ENABLED=true`로 바꾸세요.
6. 후기·구매 수·가짜 할인/마감 문구는 사실이 아니면 넣지 마세요(표시광고법 위반 소지).

## 결제(PortOne V2) 연동 순서
1. 포트원 콘솔에서 가입 후 **테스트 채널**을 먼저 만들고, Store ID / Channel Key / **API V2 Secret**을 발급받아 `.env`에 넣습니다(`PORTONE_STORE_ID`, `PORTONE_CHANNEL_KEY`, `PORTONE_API_SECRET`). 이 값들은 채팅·공개 저장소에 올리지 마세요.
2. `.env`에서 `PAYMENTS_ENABLED=true`로 바꾸고 서버를 재시작합니다.
3. 테스트 결제로 아래를 확인합니다: ① 결제 성공 → 리포트 표시 ② 결제창 닫기 → 리포트 안 열림 ③ 모바일에서 결제 후 돌아오기 ④ 콘솔에서 결제 취소(환불) 후 `orders` 상태 수동 정리.
4. 실제 결제 채널(사업자 인증 완료 후)로 교체해 소액 실결제를 시험한 뒤 오픈하세요.
5. **운영 주의**: 결제는 됐는데 브라우저가 닫혀 확인(`/complete`) 호출이 누락되면 주문이 `pending`으로 남습니다. 이 경우 고객이 “구매한 리포트 다시 보기”를 누르면 열람은 되지 않으므로, 포트원 웹훅 연동(서명 검증 포함)을 오픈 전 추가하는 것을 권장합니다. 환불은 포트원 콘솔에서 처리합니다.
6. 리포트 품질 확인만 하고 싶을 때는 `DEV_REPORT_PREVIEW=true`로 두고 `POST /api/dev/report`를 쓰세요(운영에서는 반드시 끄기).

## 요구 사항
Node.js 18 이상(내장 fetch, ICU 중국력 사용).

## 인연 캐릭터(도령·연애상대) 이미지 교체 방법
- 무료 결과에는 **모자이크(20×25 픽셀)** 만 보이고, 결제가 확인된 주문에서만 서버가 **원본**을 내려줍니다. 원본은 `private/characters/`(공개 폴더 아님)에 두세요. `public/`에는 절대 원본을 넣지 마세요.
- 지금 들어 있는 30장은 코드로 그린 **임시 일러스트**입니다. 실제 서비스용 이미지로 바꾸려면:
  1. `m_<유형>_<0~2>.png`(도령), `f_<유형>_<0~2>.png`(연애상대) 30장을 만듭니다. 유형: `dodo`(도도) `sexy`(섹시) `cute`(귀여움) `pretty`(이쁨/훈훈) `charisma`(카리스마). 4:5 비율, 600×750 이상 권장, 일상복(코트·니트 등).
  2. 같은 이름으로 `private/characters/`에 덮어씁니다.
  3. `npm i -D sharp` 후 `npm run build:characters` 를 실행하면 모자이크가 다시 만들어집니다(기존 원본은 유지).
- 이미지 제작 시 주의: 성인 캐릭터로만 만들고 노골적·선정적 표현은 피하세요(‘섹시’는 분위기·스타일로 표현). 실존 인물·연예인을 닮지 않게 하고, 생성형 AI를 쓴다면 **상업 이용 가능 여부**와 **AI 생성물 표시 의무**(국내 AI 기본법 등)를 확인해 사이트에 “AI로 제작된 이미지”를 표기하세요.
- 어떤 유형이 나오는지는 사주(일지·월지 십성)로 정해지며, 두 인연은 항상 서로 다른 유형입니다.


## UI/성별 기반 캐릭터 업데이트
- 데스크톱 콘텐츠 폭을 화면의 약 80%(최대 1440px)로 확장하고 모바일은 전체 폭을 사용하도록 반응형 레이아웃을 조정했습니다.
- 상단 바로가기, 모바일 하단 메뉴, 오늘 운세/인연/관계 리포트 하이라이트 카드를 추가했습니다.
- 무료 운세 입력에 성별 선택을 추가했습니다. 남성 사용자는 여성 캐릭터(선녀), 여성 사용자는 남성 캐릭터(도령)가 풀이 캐릭터로 배정됩니다.
- 무료 인연 미리보기에는 인연 캐릭터 한 명만 모자이크로 표시합니다. 결제 확인 후 서버가 해당 주문에 배정된 캐릭터 원본만 제공합니다.
- 유료 리포트 화면에 풀이 캐릭터의 문장을 순서대로 확인하는 인터랙션을 추가했습니다(캐릭터 패널 클릭).
- 성별 값은 리포트 생성 요청에 포함되며, 기존 주문/결제 검증 흐름은 유지됩니다.

## 이번 업데이트의 미완료 항목 / 출시 전 확인
- `private/characters/`의 30개 PNG는 기존 프로젝트에 포함되어 있던 임시 캐릭터 아트입니다. 파일 해시는 30개 모두 다르지만, 실사급 3D 한국인 캐릭터 30종으로 교체된 상태는 아닙니다. 실제 상용 이미지로 교체·검수해야 합니다.
- 캐릭터 표정 변화, 자동 립싱크, 눈 깜빡임, 카메라 컷 전환은 아직 구현되지 않았습니다. 현재 유료 리포트 캐릭터 패널에서 문장을 클릭해 순차 표시하는 방식입니다.
- 별도 PG 연동·웹훅·환불 검증, 사업자 정보 입력, 약관/개인정보 처리방침 법률 검토는 여전히 출시 전 필수입니다. `PAYMENTS_ENABLED`를 설정했다고 실제 결제 검증/웹훅까지 완성되는 것은 아닙니다.
- 실제 만세력의 절기 경계와 음력 윤달 처리 등은 별도 전문 검증이 필요합니다.
